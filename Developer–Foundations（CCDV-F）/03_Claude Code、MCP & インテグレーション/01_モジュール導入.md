## モジュール終了時にできるようになること

### Claude Codeはターミナルネイティブな開発パートナーである

これまでのモジュールでは、プロンプト、ツールスキーマ、コンテキストエンジニアリング、エージェントループ、マルチモーダル入力といった、APIの基本的な構成要素を扱ってきました。このモジュールは、その基礎の上に直接構築されています。

Claude Codeを使うと、同じモデルをターミナル環境内で操作できるようになり、パーミッション層、設定システム、チーム向けの共有機能が導入されます。MCPプロトコルにより、外部サービスとの安全な統合が可能になります。このモジュールでは、堅牢なセキュリティと効果的な展開のために、Claude CodeとMCPを設定する方法を学びます。

### 習得目標（6つの柱）

1. **パーミッションモードの選択と実行**：Claude Codeを「調査・計画・実装」のループで実行し、作業のリスクレベルに合ったパーミッションモードを選択できます。これにより、エージェントはタスクに必要以上の権限を与えられることなく生産的に作業を続けられます。
2. **コードレビューと人間によるレビューゲートの設置**：AIが生成したコードを読み、適切な水準の信頼を持って出力をレビューし、信頼できる指摘には対応し、そうでない指摘は検証し、判断を誤った場合のコストが高い箇所には人間によるレビューゲートを設置できます。
3. **永続的なプロジェクトコンテキストの付与**：CLAUDE.md、ルール指示ファイル、フック、サブエージェントを使って、Claude Codeに永続的なプロジェクトコンテキストを与えられます。
4. **ワークフローのパッケージ化**：ワークフローをSkills、カスタムコマンド、プラグインとしてパッケージ化できます。Claude Code、Messages API、Agent SDKのいずれでも同じように動作するSkillを、一度作成するだけで済ませられます。
5. **MCPサーバーの構築とスコープ設定**：ツール、リソース、プロンプトをClaudeから利用可能にするMCPサーバーを構築し、クライアントとサーバーの通信方法に合ったトランスポートを選択し、誰がそれを読み込むかを制御する設定スコープを設定できます。
6. **エンタープライズ接続とセキュリティ境界の設定**：Claudeをエンタープライズシステムに接続し、規制対象の顧客にも受け入れられるパターンでその接続を認証し、セキュリティレビューに耐えられるようコードモダナイゼーションの取り組みの範囲を設定できます。

## 本モジュールの前提と教える内容

本モジュールは、すでにコード上でClaudeを動かしているデベロッパーが、その仕組みを設定可能かつ共有可能にし、実際のシステムに安全に接続できるようにするためのものです。

- **前提条件**：モジュール2で学んだAPIパターン（エージェントループ、ツールスキーマ、コンテキストエンジニアリング）に慣れていることを前提としています。
- **本モジュールが教える4つのエンジニアリング判断**：
  1. パーミッションモデルの下でターミナルでClaude Codeを実行する方法
  2. 永続的なプロジェクトコンテキストを与える方法
  3. チームメイトがインストールできるようにワークフローをパッケージ化する方法
  4. 認証情報を漏らさずセキュリティレビューにも通るようにMCPを通じてClaudeを外部システムやエンタープライズシステムに接続する方法

## このモジュールが扱う内容

本モジュールのすべては、1つの繰り返し現れる問題を中心に構築されています：

> **「自分のマシン、自分のセッション、あるいはステージング環境で動いていたコードが、他の誰かが本番環境で、実際の企業システムに対して実行したときにも通用しなければならない」という問題**

| 環境 | 状態 | 起こりうる障害 |
| :--- | :--- | :--- |
| **自分のマシン（ローカル）** | パーミッションモードは安全に感じられる | 作業がマシンを離れた瞬間、パーミッションモードが範囲外のファイルを削除してしまう |
| **個別セッション** | プロジェクトルールは把握できる程度に小さい | 1つのルールが数百行の下に埋もれてしまう |
| **ローカル環境のSkill** | スクリプトを問題なく見つけられる | Skillが他のどのマシンにも存在しないパスを指してしまう |
| **設定ファイル** | 認証情報が設定ファイルの中にそのまま置かれている | コミットされたキーが数時間以内に漏洩する |
| **ステージングテスト** | 接続が動作している | ステージング専用の設定手順が本番環境の接続を停止させてしまう |

本モジュールで学ぶのは、どの設定上の判断がどの障害を防ぐのかを、チームメイトや監査担当者の前でそれが表面化する前に理解することです。
